Damage System

Damage Direction Indicator + Bleeding FX

The Damage System plugin provides a complete, modular solution for player damage feedback in FPS and TPS games. It includes two independent systems: a Damage Direction Indicator that shows where the damage came from, and a Bleeding FX post-process effect that splatters blood on the screen as the player takes damage.

System Overview

Damage Direction Indicator

A HUD widget that shows the direction of incoming damage using an on-screen indicator. Works in both FPS and TPS views.

Bleeding FX

A post-process material that splatters blood on the screen using a noise-driven texture. Intensity scales with damage.

Both systems work independently. You can use one, the other, or both together depending on your game's needs.

Damage Direction Indicator

The Damage Direction Indicator is a HUD element that appears when the player takes damage. It shows the direction of the attacker relative to the player's camera, with a visual indicator that points toward the source of the damage.

Related Classes

How to Set up

1. Add the AC_IndicatorWidgetManager component to your Player Character.

2. In the component's Details panel, set the Max Num Of Indicator Elements variable.
This value defines the maximum number of indicators that can appear on screen at the same time. When the limit is reached, new enemies will reuse the oldest available indicator instead of creating a new one.



3. When damage is applied, call "AssignIndicatorToEnemy(AActor Enemy)"

AC_IndicatorWidgetManager Actor Component — Damage Direction Indicator Manager

AC_IndicatorWidgetManager
Owner: Player Character
Type: Actor Component
Manages the Damage Direction Indicator widget and its pool of indicator elements. This component creates the main damage frame widget on BeginPlay and cleans it up on EndPlay. It provides a centralized reference point for accessing the indicator widget through the player character.

Variables

MaxNumOfIndicator (Integer) Variable
Description
Defines how many indicator elements the WBP_DamageIndicatorFrame should create. This is the maximum number of damage direction indicators that can appear on screen at the same time.
Default Value
4
Range
1 – 20 (recommended) — Values above 20 are allowed but may impact performance and clutter the HUD.
Effect
  • - Lower values (1–3): Fewer simultaneous indicators. Good for minimal HUD designs.
  • - Higher values (10–20): Many enemies can be tracked at once. Good for horde-style games.
  • - If the limit is reached, the oldest indicator is recycled for the newest enemy.
Notes
Tip: Set this to match the maximum number of enemies that can realistically attack the player at the same time in your game.
IndicatorFrameRef (WBP_DamageIndicatorFrame) Variable
Description
Holds a reference to the WBP_DamageIndicatorFrame widget that contains all indicator elements. This reference is created automatically in BeginPlay and can be accessed by other systems through the component.
Access
Get the component via Get Component by Class on the player character, then access this variable to get the widget reference.
Example
// Get the component from the player character Get Component by Class (AC_IndicatorWidgetManager) → Get IndicatorFrameRef → Call functions on WBP_DamageIndicatorFrame
Notes
Important:
  • - The widget is created on BeginPlay and destroyed on EndPlay.
  • - Always check IsValid before using this reference.
  • - Do not manually set this variable — it is managed automatically.

Functions

AddDamageFrameToViewPort () Function
Description
Creates the WBP_DamageIndicatorFrame widget, adds it to the viewport, and stores a reference in IndicatorFrameRef. This function is called automatically on Event BeginPlay.
Parameters
None
Returns
None
Called By
  • Event BeginPlay (automatically)
Notes
Note: You do not need to call this function manually. It is invoked automatically when the component is initialized.
RemoveDamageIndicatorFrame () Function
Description
Removes the WBP_DamageIndicatorFrame widget from the viewport. This function is called automatically on Component EndPlay (e.g., when the character dies).
Parameters
None
Returns
None
Called By
  • Event EndPlay (automatically)
Notes
Note: You do not need to call this function manually. It is invoked automatically when the character is destroyed or the level ends.

WBP_DamageIndicatorFrame User Widget — Indicator Pool and Enemy Pairing Manager

WBP_DamageIndicatorFrame
Owner: AC_IndicatorWidgetManager
Type: User Widget (UMG)
Category: Damage System
Manages the pool of indicator elements and their pairing with enemies. Creates all WBP_DamageIndicatorElement widgets on initialization and stores them in a pool. Assigns them to enemies when damage is taken and recycles them when enemies die.

Variables

AvailableIndicatorElements (Array of WBP_DamageIndicatorElement) Variable
Description
Stores all unassigned and free indicator elements. When an indicator element is assigned to an enemy, it is removed from this array and added to Enemy-IndicatorElementPair. When an enemy dies, the element is removed from the map and returned to this array.
SIZE
Equal to MaxNumOfIndicator(set in AC_IndicatorWidgetManager).
MANAGED BY
- Populated on initialization.
- Elements are removed when assigned to an enemy.
- Elements are added back when an enemy dies.
Notes
Note: This array acts as a pool of reusable widgets. Widgets are not created or destroyed during gameplay — they are recycled. This is essential for performance.
Enemy-IndicatorElementPair (Map: AActor → WBP_DamageIndicatorElement) Variable
Description
Stores the pairing between an enemy actor and the indicator element assigned to it. Used to track which indicator belongs to which enemy, so the system can update it or recycle it when the enemy dies.
KEYS
AActor_The enemy actor that dealt damage to the player.
Values
WBP_DamageIndicatorElement_The indicator element assigned to that enemy.
MANAGED BY
  • - Adds a pair when AssignIndicatorToEnemy is called.
  • - Removes a pair when the enemy dies or is no longer tracked.
Notes
Important:
  • - If the enemy is destroyed, the map entry should be cleaned up to avoid invalid references.
  • - Consider using a unique ID instead of an actor reference for more robust cleanup.

Functions

AssignIndicatorToEnemy (AActor Enemy) Function
Description
Assigns an available indicator element to the given enemy. This is the main function to call when the player takes damage. It creates a pair in Enemy-IndicatorElementPair and calls EnableDamageIndicator. on the WBP_DamageIndicatorElementto rotate it toward the enemy.
Parameters
Enemy(AActor) _ The enemy actor that dealt damage to the player.
Returns
None
Usage
Call this function from your damage-handling logic when the player takes damage. Pass the enemy that caused the damage.
Example
Event OnTakeAnyDamage (Damage Causer) → Get AC_IndicatorWidgetManager (on Player Character) → Get IndicatorFrameRef → AssignIndicatorToEnemy - Enemy: Damage Causer
what it does
  • - Calls EnableDamageIndicator on the assigned WBP_DamageIndicatorElement.
  • - Removes the element from AvailableIndicatorElements.
  • - Adds the pair to Enemy-IndicatorElementPair.
Notes
Important:
  • - If the enemy already has an assigned indicator, the existing one is reused.
  • - If no elements are available, the oldest pair is recycled.
  • - The indicator rotates to face the enemy automatically.

WBP_DamageIndicatorElement User Widget — Single Damage Direction Indicator

WBP_DamageIndicatorElement
Owner: WBP_DamageIndicatorFrame
Type: User Widget (UMG)
Category: Damage System
A single indicator element that rotates toward its paired enemy. Each element is part of a pool managed by WBP_DamageIndicatorFrame. When enabled, it follows its enemy for a set duration, then returns to the pool.

Variables

IndicatorTimer (Float) Variable
Description
Defines how long (in seconds) the indicator should follow its paired enemy. When the timer expires, the widget is disabled and returned to the AvailableIndicatorElements array in WBP_DamageIndicatorFrame.
Default Value
2.0 seconds
Range
0.5 – 5.0 (recommended) — Values below 0.5 make the indicator hard to notice. Values above 5.0 may clutter the screen.
Effect
  • - Short duration (0.5–1.0s): Brief flash of direction. Good for fast-paced games.
  • - Long duration (3.0–5.0s): Persistent indicator. Good for tactical games.
Notes
Tip: This value is typically set in the parent widget (WBP_DamageIndicatorFrame) and passed to each element when it is created.

Functions

EnableDamageIndicator (AActor EnemyRef) Function
Description
Makes the indicator's image widget visible and starts a timer for updating the rotation of the element toward the paired enemy. This function is called by AssignIndicatorToEnemy and should NOT be called directly.
Parameters
  • EnemyRef (AActor) — The enemy actor this indicator should follow.
Returns
None
Usage
⚠️ DO NOT CALL THIS FUNCTION DIRECTLY.
Use AssignIndicatorToEnemy instead.
Why Internal
  • - This function assumes the indicator element has already been prepared by the frame.
  • - Calling it directly may result in unpaired indicators or broken cleanup logic.
  • - It does not handle pooling or enemy pairing.
Called By
  • AssignIndicatorToEnemy (WBP_DamageIndicatorFrame)
Notes
Tip: If you need to show an indicator, call AssignIndicatorToEnemy instead. This function exists so that the frame can control the lifecycle of each indicator element.
DisableIndicatorElement (AActor EnemyRef) Function
Description
Hides the indicator's image widget, clears the rotation timer, and resets the element. This function is called when the paired enemy becomes invalid (e.g., the enemy dies) or when the IndicatorTimer expires.
Parameters
(AActor EnemyRef)
Returns
None
Called By
  • - its own, checks if enemy ref is invalid(when the enemy dies).
  • - The IndicatorTimer (when it expires).
Notes
Note: After this function runs, the element is returned to the pool (AvailableIndicatorElements) of WBP_DamageIndicatorFrame and can be reused for another enemy.

Bleeding FX

The Bleeding FX is a post-process material that splatters blood on the screen when the player takes damage. The effect uses a noise-driven texture mask to create an organic, non-repetitive blood pattern that feels natural and immersive.

Related Classes

How to use

1. Add "AC_Blood Fx" component to player character

2. call "BleedingFX(float BloodIntensity, float duration)" on damage applied

AC_BloodFX Actor Component — Bleeding FX Manager

AC_BloodFX
Owner: Player Character
Type: Actor Component
Category: Damage System
Manages the Bleeding FX post-process material applied to the player's camera. Controls blood intensity and fading through a Material Parameter Collection (MPC_Blood). The material is set on the camera on BeginPlay and updated during gameplay.

Variables

BloodFade (Float) Variable
Description
Controls the current fade amount of the blood effect. This value is clamped between 0 and 100 and is used to drive the opacity of the blood material.
Range
0 – 100
Notes
Do Not Change: This variable is managed internally by the component. Modifying it manually may break the fading logic.
TimerParam (Float) Variable
Description
Used for fading the blood effect over time. This value is incremented or decremented to create the fade animation.
Notes
Do Not Change: This variable is managed internally by the component.
MinBloodFade (Float) Variable
Description
The minimum value used in the Map Range Clamped node for blood fading. Default value is 1.0.
Range
1.0 (default)
Notes
Note: This is used with MaxBloodFade to map the fade range. You typically don't need to change this.
MaxBloodFade (Float) Variable
Description
The maximum value used in the Map Range Clamped node for blood fading. Default value is 1.7.
Range
1.7 (default)
Notes
Note: This is used with MinBloodFade to map the fade range. You typically don't need to change this.
BloodIntensity (Float) Variable
Description
Defines how much blood should be splatted on screen. This value is passed to the material via the MPC_Blood and controls the overall opacity of the blood effect.
Range
0 – 100
Effect
  • Low values (10–30): Light blood splatter. Good for minor damage.
  • Medium values (40–70): Moderate blood. Good for sustained damage.
  • High values (80–100): Heavy blood. Good for critical damage or near-death.
Notes
Tip: This value is typically set by the BleedingFX function based on the damage taken.
BleedingTime (Float) Variable
Description
Defines how many seconds the blood should remain on screen before it begins to fade. This value is passed to the BleedingFX function.
Range
1.0 – 10.0 (recommended)
Effect
  • Short duration (1–3s): Quick fade. Good for fast-paced games.
  • Long duration (5–10s): Persistent blood. Good for immersive, tactical games.
Notes
Tip: Set this value when calling BleedingFX to control how long the blood stays on screen.
IsBleeding (Boolean) Variable
Description
Tracks whether the player is currently bleeding. Used by the BleedingFX function to decide whether to set a random normal for the material (no blood on screen) or to increase the blood over the existing one.
Effect
  • True: Blood is already on screen. New blood is added on top of the existing effect.
  • False: No blood on screen. A new blood effect is created with a random normal.
Notes
Note: This is managed internally by the component. You typically don't need to change it.

Functions

BleedingFX (float BloodIntensity, float Duration) Function
Description
Splats blood on the screen and fades it over the specified duration. This is the main function to call when the player takes damage.
Parameters
  • BloodIntensity (Float) — How much blood should be splatted on screen. Range: 0 – 100.
  • Duration (Float) — How many seconds the blood should remain on screen before fading.
Returns
None
Usage
Call this function from your damage-handling logic when the player takes damage. Pass the desired intensity and duration.
Example
Event OnTakeAnyDamage (Damage Amount) → Get AC_BloodFX (on Player Character) → BleedingFX - BloodIntensity: Damage Amount * 2.0 - Duration: 3.0
Notes
Important:
  • If blood is already on screen, the new blood is added on top of the existing effect.
  • The IsBleeding variable is used internally to determine whether to create a new effect or add to an existing one.
  • The blood fades over the specified duration.

Demo Porject

The plugin includes a fully integrated demo project that demonstrates how to use the Damage System in a real gameplay scenario. It serves as a practical case study for integrating the plugin into your own project.

What's Included

- Weapons that fire projectiles with a AC_DamageComponent that applies damage on hit.
- Player Character, has AC_HealthComponent that calls the Damage System functions (Indicator and BleedingFX).
- Falling Damage System that applies damage when the player falls from a great height.

How to Run the Demo

1. Set the BP_DamageSystemGameMode as Defautl Game mode
2. Open Lvl_Damage in Demo files
3. Play the Demo
